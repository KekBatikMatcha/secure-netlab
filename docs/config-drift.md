# Config backup and drift detection (Phase 2)

The `automation` package backs up device configs on a schedule, keeps versioned copies, and
compares each new backup with an approved baseline.

## Commands

```bash
python -m automation baseline router   # accept the current config as the approved baseline
python -m automation check             # fetch all devices, store changes, report drift
python -m automation run --every 300   # repeat check every 5 minutes (Ctrl+C to stop)
```

`check` exits 0 when everything matches, 1 when drift is found, and 2 when a device could not be
collected. Schedule it with cron or Windows Task Scheduler if you don't want the long-running loop.

Typical workflow: make an intended change, run `check`, review the drift report, and if the change
is approved run `baseline <device>` so it becomes the new reference.

## What is collected

Devices are listed in `inventory/devices.yaml`. Each device has named sections, and each section is a
read-only command run inside its lab container:

| Device | Section   | Command                    | Checks                              |
|--------|-----------|----------------------------|-------------------------------------|
| router | firewall  | `iptables-save -t filter`  | chain policies and FORWARD rules    |
| router | listeners | `netstat -tln`             | open TCP ports                      |
| plc    | listeners | `netstat -tln`             | open TCP ports                      |

Collection uses `docker compose exec`, so the lab needs no SSH. A Netmiko/SSH fetcher can replace
it later through the same `fetch(device)` interface.

## Storage

- `backups/<device>/<UTC timestamp>.cfg`: one file per version that differed from the previous one.
- `golden/<device>.cfg`: the approved baseline, committed to git.

Configs are normalised before they are stored or compared. Packet counters (`[12:720]`), comments
(including the "Generated by" timestamp), loopback-only listeners, and listener order are removed.
A poll that changes only those produces no new version and no drift.

Loopback listeners are ignored on purpose. Docker's embedded DNS listens on `127.0.0.11` with a new
random port on each start, so keeping it would report drift on every restart.

## Drift rules

| Kind                     | Severity | Meaning                                                        |
|--------------------------|----------|----------------------------------------------------------------|
| `policy-changed`         | high     | a chain's default policy changed (e.g. FORWARD DROP to ACCEPT) |
| `firewall-rule-added`    | high/medium | new rule; high if it ACCEPTs a sensitive port                |
| `firewall-rule-changed`  | high/medium | one removed + one added rule with the same src/dst/proto/action |
| `firewall-rule-removed`  | medium   | rule removed with no matching replacement                      |
| `listener-added`         | high/medium | new listening port; high on a sensitive port                 |
| `listener-removed`       | low      | a listening port stopped                                       |
| `section-missing`        | medium   | a section in the baseline was not collected                    |

Sensitive ports are 22, 23, 80, 443, 502 (Modbus/TCP) and 830 (`automation/drift.py`). Modbus is
included because an allow rule to the PLC from an unexpected segment is as serious as an admin port.

Limitations:
- Rule order is not compared. Reordering iptables rules is not reported.
- A rule change is paired only when the match is unambiguous. If two rules share the same
  src/dst/proto/action, the change shows up as a removal plus an addition.

## Tests

- `tests/test_bundle_drift.py`: normalisation and drift cases, using the sample configs in
  `tests/fixtures/` (`router_baseline.cfg`, `router_counters_only.cfg`, `router_drift.cfg`).
- `tests/test_store_schedule.py`: versioning, deduplication, failure isolation, scheduler, exit codes.
- `tests/test_fetch_inventory.py`: docker command construction, partial-failure handling, inventory validation.
- `tests/integration/test_backup_live.py`: backs up the live lab and compares it with `golden/`.

Live drift check (run during Phase 2): a telnet listener on the PLC and an extra management-port
allow rule on the router were each reported as high severity. Removing them returned the lab to
no drift.
